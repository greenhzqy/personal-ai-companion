# personal-ai-companion · 给你自己造一个 AI 伙伴

> **这是给人看的说明。** 给 AI 读的执行指令在 `SKILL.md`（装好之后它会自己读）。
> 你要做的只有三件事：**放对目录 → 说一句话 → 按它给的阶段走**。

---

## 这是什么

一套**八阶段流程 + 可直接跑的骨架**，用来把一个真实的人（你自己）变成一套属于他的 AI 系统：

```
采集访谈 → 人格档案 → 常驻载体 → 感知闭环 → 工程化 → 状态面板 → 脱敏发布 → 对外表达
```

它不是「写一段人格提示词」。它要交付的是一套**住在你电脑里、自己知道你在不在、不用你打卡**的东西——
桌面壁纸里的角色、悬浮球、托盘程序都行。

**核心判断**（也是这份 skill 存在的原因）：

> 陪伴类 AI 活不下来的原因几乎从不是技术，而是**它要求你主动打开、还要打卡**。那你凭什么坚持？

参考实现是一个真实做出来的东西：**陪伴精灵 Green**（见下「参考实现」）。

---

## 它适合你吗

| 适合 | 不适合 |
|---|---|
| 你想让一个 AI **真的陪着你**，而不是你伺候它 | 只想要一段角色扮演提示词 |
| 你愿意花几小时做一次**关于自己的访谈** | 不想做访谈、也不想让它了解你 |
| 你能接受「先有档案、再有界面」的顺序 | 只想马上看到一个能动的 demo 且拒绝阶段 1–2 |

> 一句话判据：**如果你不打算让它自己知道你在不在，你不需要这份 skill。**

## 三步上手

**1. 放到你的 skills 目录**

整个 `personal-ai-companion/` 文件夹复制到你的 skill 目录下，例如：

```
~/.dsh/skills/personal-ai-companion/          # DSH
~/.claude/skills/personal-ai-companion/       # Claude Code 等
```

> 目录名**必须**是 `personal-ai-companion`（skill 的 `name` 要与目录名一致，这是规范要求）。

**2. 对你的 AI 说一句话**

它靠描述触发，试这些说法：

> 「我想做一个自己的 AI」「做一个我的数字人格」「桌面宠物 / 个性壁纸」
> 「让 AI 真的陪我」「复刻陪伴精灵」

**3. 按阶段走，别跳**

它会先问你三个问题（形态 / 你最常看的屏幕 / 让它管什么），然后从阶段 1 开始。
**每个阶段都有产出物和验收标准**，产出落到文件，别只留在对话里。

> ⚠️ **别一上来就问使用者"你手上有什么材料"。** 正确顺序是
> **先访谈（聊）→ 再建模 → 最后才拿 `templates/素材清单.md` 当检查表对一遍**。 <!-- order-sentinel -->
> 那份清单是**采集者自己用的**，**不要逐类发给他勾**（依据：一位真人的反馈，
> 详见 `CHANGELOG.md` 的 v2.1 与 `templates/素材清单.md` 顶部）。

| 项 | 要求 |

| 系统 | **Windows**（当前所有实测都在 Windows 上；见「已知限制」） |

## 参考实现

**<https://github.com/greenhzqy/green-pet-wallpaper>** —— 一个真实做出来、并且跑在作者桌面上的成品。

**边界要说清**（重要）：

- 那个仓库公开的是**运行时部分**（壁纸、3D 宠物、键盘跟随、感知服务、看门狗、护屏）；
- **人格档案部分不公开**——它包含作者的真实身份、经历与自省内容，属于隐私；
- 所以它是「阶段 3–5 的实例」，**不是阶段 1–2 的实例**。人格那部分你得自己采。

## 已知限制（先看，省得白费时间）

| 限制 | 说明 |
|---|---|
| **只在 Windows 上端到端验过** | 骨架用了 PowerShell + Win32 API。macOS / Linux 的对应实现只在 `scripts/README.md` 里给了 API 名称，**那是设计，不是实现** |
| **阶段 6/7/8 尚未验收** | 面板、发布、对外表达这三段还没经过独立验收；写它们的参考文件也明显更薄 |
| **没有一个真人用它走完全程** | 四轮验收验的是「另一个 AI 能不能照着执行」，用的是虚构人物。**真实使用者的反馈还没进来** |
| **新版采集入口未在真人身上验证** | v2.1 把入口整个推翻（"不再盘问"）之后，**只做过一次不知情子代理的措辞盲测**，而那个子代理扮演的人**几乎就是作者本人**——**它没有证明"陌生人会用得上"**。详见 `VERIFICATION.md` 与 `projects\清单新人验证\入口实测\` |
| 壁纸引擎的实际挂载没在本包内验过 | 需要你自己装（如 Lively Wallpaper）并手动操作 |
| 长时间运行（24h+）未验证 | 内存/日志增长类问题可能在长跑后出现 |

## 它会碰你的隐私吗

这份 skill 教的东西**包含感知能力**（键鼠空闲秒数、前台程序名），所以边界必须说清：

- **只在你自己的机器上装。** 别把它装到别人的电脑上——那是监控，不是陪伴。
- 感知层**只收事实**：空闲秒数 + 前台进程名。**不记录你打了什么、不存窗口标题历史**。
- 键盘跟随只上传**虚拟键码**，永不解析成字符，**一个字都不落盘**。
- 服务只监听 `127.0.0.1`，数据不出本机。
- **人格档案会在你机器上留下大量私密内容**（家庭、恐惧、私人事务）。它默认不进任何公开产物——
  发布前用 `references/7-发布与脱敏.md` 的脚本扫一遍，**靠扫描，不靠印象**。

## 想贡献 / 报告问题

最有价值的反馈不是"写得不错"，而是**你在哪一步卡住了**：

- 哪一节的指导不够、你只能靠猜？
- 有没有哪条规则自相矛盾，或跟你的真实情况对不上？
- 骨架在你机器上跑不起来？把命令和报错贴出来。

按 `CHANGELOG.md` 的格式追加一条，或直接改文档并说明理由。**改之前先跑一遍改动那节的一致性检查。**
