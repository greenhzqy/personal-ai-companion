# 阶段 3 · 常驻载体与个性化：让它住在你每天都看得见的地方

> 前面两阶段决定它**懂不懂你**，这一阶段决定它**能不能活下来**。
> 一个需要你主动打开的 AI，使用频率会在两周内掉到零。

---

## 一、先选载体：三种路线的真实代价

| 载体 | 你看到它的概率 | 真实代价 | 适合谁 |
|---|---|---|---|
| **桌面壁纸层**（Lively + WebGL/HTML） | **最高**——你天天回桌面 | 要装壁纸引擎；渲染在桌面图标**之下**；常规截屏抓不到 GPU 合成层；全屏应用下看不到 | 想要「住在那儿」的存在感 |
| **悬浮窗 / 悬浮球** | 高，但会被遮挡 | 挡住操作、被全屏应用覆盖、要自己处理置顶与透明、透明窗口技术坑多 | 想随时能点它 |
| **托盘图标** | 低 | 存在感最弱，只能提示 | 只要后台能力，不要存在感 |
| **手机锁屏 / 小组件** | 高，但和你用电脑的时间错开 | 跨设备同步麻烦 | 主要在手机上的人 |

**决策问题（照 SKILL.md 阶段 0 第 2 问）**：
> 你一天里最常看的那块屏幕上，**有没有人在看**？

本项目的教训值得抄一遍：当事人有一台长期放在工位、用平板远程的机器。有人为「你看着桌面时的流畅度」把帧率一路拉到刷新率上限——而那块屏**根本没人看**，还 24 小时亮着。**优化之前先确认使用场景。**

## 二、壁纸层实操要点

1. **壁纸就是一个本地 HTML 页面。** 用壁纸引擎（Lively 等）「添加壁纸 → 浏览」，指向你的 `wallpaper.html` 即可，不需要插件或打包。
2. **数据由本地服务提供**（例：`127.0.0.1:<端口>`）。页面 `fetch` 本机接口拿状态、语气、统计。**不要**把数据直接写死在页面里，否则改一次要重载壁纸。
3. **改完必须同步到壁纸库副本并重启引擎才生效。** 引擎会把壁纸复制到自己的库目录（例：`...\Library\wallpapers\<你的目录>\`）。**源码目录改了不等于壁纸变了。**
   > 本项目踩过：一直改源码、壁纸纹丝不动，查了半天。真凶是**旧目录还有一份副本**，启动项指向的是旧那份。**排查方法：看进程的实际命令行，别猜。**
4. **壁纸层的取数通道要选可靠的。** 壁纸引擎的宿主消息协议（postMessage 那类）可能**根本没送达**——本项目实测用户设的参数一直没生效。更可靠的做法是让服务端**直接读配置文件**，或者用「图片信标」(`new Image().src=...`) 上报——它不会被跨源策略挡。
5. **图片信标适合"只上报不要回包"**；需要回包就用 `fetch` 到本机 `127.0.0.1`（同源策略对本机端口同样适用，记得服务端发 CORS 头）。

6. **★ 全屏层的坐标系是"整屏"，不是"工作区"。**
   这是个必踩的坑：屏幕（`Bounds`）含任务栏高度，工作区（`WorkingArea`）不含。壁纸铺满整屏，而你的 UI 若按"底部 30px"定位，**就会被任务栏盖住一截**（本项目实测：整屏 1067 vs 工作区 1019，任务栏 48px → 对话框有 18px 埋在任务栏下面）。
   > **修法**：**单一真源常量**（例：`--taskbar-h: 48px`），UI 内边距写成 `calc(24px + var(--taskbar-h))`。以后改任务栏高度只动一个数。
   > **原则**：全屏层按**屏幕物理边界**定位，UI 内边距按**工作区边界**留。

7. **宿主应用"点了没反应"时，先去看宿主自己的日志。**
   本项目遇到"在壁纸软件里点了设为壁纸却没反应"。真凶不在自家代码里——宿主日志显示它的内核进程 `Unresponsive` 之后，旧进程被摘掉但再也创建不出新的。**重启宿主即恢复。**
   > **做法**：找到宿主的日志目录，**比对成功与失败两条流程的日志序列差异**（成功的路径长什么样、失败在哪一步断掉）。这比在自家代码里瞎找快得多。

## 三、个性化的三条原则（怎么才不像模板）

### 原则一：不要 emoji，自绘图标
这是**单条性价比最高**的「去 AI 味」手段。哪怕你只画 10 个 SVG 图标，观感也和 emoji 拼凑的东西完全不同。
> 理由不是审美洁癖：emoji 是别人的字体、别人的配色、别人的风格，一眼就是「默认值」。

### 原则二：排版比配色重要
对齐、行高、字号层级、留白节奏——**改排版对"像不像人做的"影响远大于换配色**。中文还要单独调：标点挤压、中英混排间距、行高比西文更大。

### 原则三：只属于你
- **署名系统**：开机签名 → 角落落款 → 作者页，三层。别人一看就知道是谁做的（也是你能发朋友圈的原因）。
- **只有你懂的素材**：你喜欢的音乐/照片/口头禅/纪念日。**注意版权——别把别人的照片和歌词打包进公开仓库**（见 `references/7-发布与脱敏.md`）。
- **你的性格参数**：属性条、台词、吐槽，全部从阶段 2 的 L3 内容包长出来，不要凭空编。

### 3D 细节（如果做 3D）
> **「颜色不够深」通常不是 albedo（基色）的问题，是 specular / clearcoat / 环境贴图的白色叠加在冲淡它。**
> 先调光泽与反射，再动基色——本项目实测主体像素从 `#8CD39A` 压到 `#5BBA75`，靠的是前者。

## 四、开机自启：三条路，按可行性排序

**不要只给一条路**——受限环境下注册表写入会被拒、`schtasks` 会失败。
按下面顺序试，第一条不通就退到下一条，**每条都附验证方法**。

### 路 1 · 启动文件夹快捷方式（最稳，不需要任何权限）

```powershell
$startup = [Environment]::GetFolderPath('Startup')
$lnk = Join-Path $startup "我的伙伴.lnk"
$ws = New-Object -ComObject WScript.Shell
$s = $ws.CreateShortcut($lnk)
$s.TargetPath = "wscript.exe"
$s.Arguments  = '"' + (Join-Path $PSScriptRoot "_watchdog.vbs") + '"'
$s.WorkingDirectory = $PSScriptRoot
$s.WindowStyle = 7          # 最小化，避免闪窗
$s.Save()
```
**验证**：`Get-ChildItem ([Environment]::GetFolderPath('Startup'))` 能看到那个 `.lnk`，
且**双击它能真的起来**（先手动双击测一次，别只信"文件在那儿"）。

### 路 2 · 注册表 `HKCU\...\Run`（不需要管理员，但可能被策略拒）

```powershell
Set-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' `
  -Name 'MyCompanion' -Value ('wscript.exe "' + (Join-Path $PSScriptRoot "_watchdog.vbs") + '"')
```
**验证**：读回实际值确认，**不是看命令有没有报错**——
```powershell
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' | Select-Object MyCompanion
```
> 本项目踩过：脚本"执行成功"，但注册进去的是**乱码路径**，自启永远不生效且**不报错**。
> 所以必须**读回实际值**核对。

### 路 3 · 计划任务（能力最强，但最容易被拒）

```powershell
schtasks /create /tn "MyCompanionWatchdog" /sc minute /mo 10 `
  /tr "wscript.exe \"<这里换成 _watchdog.vbs 的绝对路径>\"" /f
```
**验证**：`schtasks /query /tn "MyCompanionWatchdog" /v /fo LIST` 看**实际命令行**与上次运行结果。

> ⚠️ **受限环境下的现实**：验收实测中，注册表写入被拒、`schtasks` 也失败。
> 这时**不要硬刚**，退回路 1，并把"自启未验证"如实记下来。
> **还有一个更彻底的兜底**：如果这台机器上已经有别的开机自启机制（例如你已有的某个计划任务、或壁纸引擎自己的自启），
> **让你的看门狗挂在它下面**，而不是新建一条。

## 五、壁纸引擎的路径：别猜，去问系统

"常见安装位置"**经常猜不中**（验收实测：三个猜测路径全落空，而机器上其实装了）。

```powershell
# 引擎正在跑的时候，直接问它：
Get-Process Lively | Select-Object -ExpandProperty Path
# 或者从已有的启动项/快捷方式里读实际目标
```
拿到真实路径后写进环境变量覆盖位（如 `HOST_EXE`），**比列一堆猜测路径可靠得多**。

## 六、产出物与验收

**产出物**：一个**能开机自启、不弹窗、不挡操作**的实体。

- [ ] 连续开机 3 天它还在（不是重启后消失）
- [ ] 开机自启是**静默**的——不弹控制台黑框、不弹大窗口
  > 黑框闪烁是「廉价感」的主要来源。Windows 上用 `wscript` 的 `Run(..., 0, ...)` 起 PowerShell，而不是直接跑 `powershell.exe`。
- [ ] 改一次源码 → 同步到运行副本 → 重启引擎 → **肉眼看得到变化**（这条链路要跑通一次，别假设它通）
- [ ] 它出现在你**不特意去看也会看到**的地方
- [ ] 你自己看着它**不觉得尴尬**（这一条比任何指标都重要）

## 七、常见失败

| 症状 | 真凶 | 修法 |
|---|---|---|
| 改了源码壁纸没变 | 运行的是另一份副本 | 看进程实际命令行，合并副本、消除歧义 |
| 参数设了不生效 | 宿主消息协议没送达 | 服务端直接读配置文件 |
| 壁纸里数值是旧的 | 数据写死在页面里 | 改成从本地服务取 |
| 开机后它不在 | 自启没注册成功 / 注册到了乱码路径 | 注册表 `HKCU\...\Run` 里查实际值；中文路径的 `.bat` 要 GBK 编码 |
| 全屏游戏时它消失了 | 壁纸层在应用之下，正常现象 | 别为此加"强制渲染"标志（见阶段 5） |
| 界面上写着能点，实际点不动 | **删功能时没检查承诺它的样式**——CSS 里还留着 `cursor:pointer` + `:active{cursor:grabbing}`，但事件监听器压根不存在 | **CSS 里的交互性提示是设计承诺，不是实现。** 删功能时要连带搜索承诺它的样式；补回监听器后要用 `elementFromPoint` + 真实事件验证三条入口各司其职 |
