# 阶段 4 · 感知与陪伴闭环：让它不用你打卡就知道你在

> 这是整套系统里**最不可替代**的一环。
> 功能可以少，但「它自己知道你在不在」这件事必须有——否则它就退化成又一个需要你主动打开的工具。

---

## 一、那条把项目救回来的反馈

本项目在「游戏化打卡面板」阶段卡了很久，用户一句原话推翻了全部前提：

> 「我好久没用了，但我经常用电脑；我希望他真的陪我，而不是我要自己打开、还要打卡，像做任务。」

**诊断**：问题不在功能少，在**关系反了**——它要求用户为它做动作（打开、打卡、汇报）。正确的方向是：**它为用户做动作**。

改造后的三条：
1. **感知**：它自己判断你在不在电脑前、在干什么；
2. **自动记录**：活跃时长自动累积成经验值，**不用打卡**；
3. **不打扰**：你离开它就完全安静。

---

## 二、感知层的最小实现（Windows）

**只用两个 Win32 调用就够**：

| 拿什么 | 用什么 | 得到 |
|---|---|---|
| 你多久没动键鼠 | `GetLastInputInfo` | 空闲秒数 |
| 你在用什么程序 | `GetForegroundWindow` + 进程名/窗口标题 | 前台程序与标题 |

把这两个值算出来，就能做出**自动分类**：

```
code / terminal / browse / chat / video / doc / game / other
```

**分类靠一张进程名映射表**（把 `chrome → browse`、`code → code` 这样列出来），
可直接用 `scaffolds/_sense.ps1` 里那张表当起点，按你自己常用的软件改。

> ⚠️ **`game` 这一类用上面两个调用判不出来。** `GetLastInputInfo` + `GetForegroundWindow`
> 只能告诉你"前台是谁"，判不出"是不是全屏独占"。要么额外查全屏状态
> （比较前台窗口 rect 与显示器 rect），要么**先不做这一类**——
> 把它粗暴归进 `other` 比给一个不准的标签好。

**实现方式**：起一个本地服务（Node 零依赖即可），让服务去调一次 PowerShell 拿这两个值，
转成 JSON 暴露成一个接口（例：`GET /sense`）。

> ⚠️ **这里有一个会当场崩的坑，先看再写**（验收实测：6 种写法里只有 1 种能活）：
>
> 在受限环境（沙箱、部分安全策略下）里，**子进程的管道 stdio 是被禁止的** ——
> `spawn` / `execFile` / `exec` 用默认或 `'pipe'` 会直接抛 `EPERM`。
> 能用的只有一种组合：
> ```
> stdio: 'ignore'   ＋   让 PowerShell 自己把 JSON 写进一个文件，Node 再读那个文件
> ```
> - `stdio: 'inherit'` **读不回值**——输出只落在控制台，Node 拿不到；
> - `stdio: 'ignore'` 而不让子进程自己写文件 = **静默无输出**（最难查的一种）；
> - 每次 spawn 实测 **476–489ms**（见阶段 5 的"取数成本"一节），所以**必须缓存**。
>
> 可直接用的实现见 `scaffolds/sense-server.js`（含每个请求一个独立输出文件、避免竞态的写法）。

> **跨平台对应**：macOS 用 `CGEventSourceSecondsSinceLastEventType` + `NSWorkspace.frontmostApplication`；Linux 用 `xprintidle` + `xdotool getactivewindow`。**思路完全一样**，换的是取数方式。

### 三个必须注意的细节

1. **响应头要显式声明 `charset=utf-8`。** 否则调用方（尤其 PowerShell 的 `Invoke-RestMethod`、部分客户端）会按 Latin-1 解码，**中文窗口标题全乱码**。
2. **接口只输出事实，分类是"薄的一层"且只放一处。** 感知层输出原始事实（空闲秒数、进程名、标题）；**分类表放在取数那一段（生产者侧），不要在消费端再分一次**——两边各写一套，改一处就会不一致。消费端只按 `activity` 字段取用。
3. **采样的时机决定数据新旧。** 若消费端用长轮询，**数据是在请求发起那一刻采样的**——空闲时挂着的请求返回的是十几秒前的快照。**别拿它当"现在"。**（这是本项目被骗了三次的坑，详见 `references/6-验证纪律.md`）

### 取数之后：推送，而不是轮询

如果它要对你的动作**实时反应**（例：你按下一个键，它立刻抬脚），**定时轮询会成为最大瓶颈**。

本项目的真实数字：链路是「键盘采样 24ms → 攒批 90ms → 客户端每 420ms 轮询一次」→ **最坏 ~530ms**。用户的原话是「响应速度不够快且不流畅有点卡顿」，而 AI 一开始怀疑的是 GPU——**真凶是那个 420ms 轮询**。

**改成长轮询后的效果：实测 11ms，而且空闲时一个请求都不发。**

**做法（可直接照抄）**：
```
客户端：GET /keys?since=<我已知的计数>
服务端：计数没变 → 把响应挂着（设 25s 超时）
        有新数据（POST /keys 到达）→ 立刻 flush 所有挂起的响应
```
**长轮询的两个附带好处**：空闲时**零请求**（比高频轮询更省电、更适合长期挂机）；不需要 WebSocket 那种长连接管理。

> **⚠️ 这条链路少一半就动不起来**：长轮询只负责"服务端把事件推给页面"，
> **上游还得有一个真正读键盘的进程**在按键时 `POST /keys`。
> 只照抄长轮询、不写上游，页面会一直安静地等——而且**不报错**（这就是"静默无输出"那一类坑）。
> 上游实现见 `scaffolds/_keywatch.ps1`（轮询 `GetAsyncKeyState`，只上报虚拟键码）。

> **通用教训：找性能问题先算"延迟链"，把每一段的最坏延迟写出来。** 卡顿的真身经常是链路而不是渲染。

## 三、自动累积：把打卡彻底删掉

**规则设计（照抄可用）**：

| 参数 | 建议值 | 含义 |
|---|---|---|
| 判定"在用电脑" | 空闲 ≤ 120s | 键鼠没动超过 2 分钟就算离开 |
| 奖励粒度 | 每累计 1000s | 约 17 分钟活跃 |
| 每粒度奖励 | +5 XP | 数值本身不重要，**节奏**重要 |
| 离开判定 | ≥ 300s | 超过 5 分钟视为离开，**完全不打扰** |

> ⚠️ **注意这里有两套不同的阈值，别混成一套**（验收实测发现文档没说清，容易被读成"缺了 120–300s 这一档"）：
> - **累积轴**（奖励逻辑）：`≤120s` 算"在用"，`≥300s` 算"离开"——中间那 120–300s **故意的**：
>   短时间离开不该中断累积，也不该立刻算离开。这段时间**照常算在用、但不说打扰的话**。
> - **表现轴**（动画/护屏档位）：`15s → idle`、`150s → away`（见阶段 5 的性能闸门）。
>
> 两条轴服务不同的目的，**可以不同值**。写代码时把它们命名成两组常量
> （例：`USING_PC_SEC` / `AWAY_LEAVE_SEC` 与 `IDLE_AFTER` / `AWAY_AFTER`），
> **不要共用一个 `idleSec` 判断**——否则以后调其中一个必然破坏另一个。

**关键点**：
- **累积的是"陪伴时长"，不是"完成任务"**——这样它奖励的是你**在用电脑**这件事本身，你不需要为它做任何额外动作。
- **奖励要幂等**：记录「已经给到第几档」（`xpGiven`），重算时只补差额。否则重算一次就多发一次。
- **每日重置**：分天统计（`activeSecToday`），否则数字只增不减，很快失去意义。

## 四、主动说话：节流是生死线

一个会说话的伙伴，和一个会烦人的程序，**只差一个节流设计**。

**必须有的四条规则**：

1. **不打扰区间**：你离开（≥300s）时**完全静默**，一句都不说。
2. **频率上限**：每次主动说话之间有最小间隔（例：3 分钟），且**同类话术不得连发**。
3. **按情境选话**：不是随机抽，是**按状态选**。可用的一套：
   | 情境 | 话 |
   |---|---|
   | 刚回来 | 「你回来啦」 |
   | 连续坐了 90 分钟 | 「起来倒杯水」 |
   | 写代码 45 分钟 | 「眼睛歇一下」 |
   | 深夜还在用 | 引**他自己定过的**作息线（照抄他的话，别用通用劝睡） |
   | 刚拿到奖励 | 「陪了你 X 分钟，自动的，不用打卡」 |
4. **话要短、要具体、要像你自己说的**。台词从阶段 2 的 L3 内容包里取，**不要写「加油」「你真棒」这类通用语**。

> 判断标准：**如果这条话术发给一个陌生人也不违和，它就是废话。** 好的台词只对他成立。

## 五、可见的积累 > 数值的增长

等级从 1 涨到 19，用户是**没有感觉**的。有感觉的是**能一眼看到的形状**：

- 一天 24 小时的活动环（哪几小时在、哪几小时空）
- 一周/一月的时间热力图
- 「今天陪了你 X 分钟」这种**可比较**的数字（和昨天比，不是和全世界比）

**设计原则**：把时间变成**形状**，把抽象变成**可比较**。

## 六、记忆与自省（可选但强烈建议）

**先解决"愿不愿意用"，再谈记什么。** 本项目有一次用户反馈「我还是没有什么主动使用的欲望」，AI 的**第一反应是加更多动效——这是错的**。真实诊断是三条：

| 问题 | 证据 |
|---|---|
| 记录一件事要 **6 步** | 双击宠物 → 面板打开 → 找到入口 → … |
| 宠物**从不向你索取**任何东西 | 它是个家具，不是伙伴 |
| **积累不可见** | 攒了数值，但你在屏幕上根本看不到它 |

> **修法不是加功能，是把"记录"从 6 步压到 1 步，并让积累出现在天天看的地方。**
> 落地手段：一个随时可写一句话的小窗（不打开主界面，回车保存、自动关闭）。**降低摩擦永远比增加功能有效。**

在此之上再谈记忆：
- **记一笔**：一个随时可写一句话的小窗（不用打开主界面）。写完自动关，不打断。
- **它记得**：下次能说出「你昨天写的是 X」。
- **每周自省**：固定时间问几个问题（**问题从阶段 1/2 的材料里长出来**，不要套模板），答案回写到人格档案（阶段 2 的更新机制）。

> 这一环让整套系统**自身会成长**，而不是永远停在出厂人格。

## 七、隐私红线（不可协商）

| 红线 | 做法 |
|---|---|
| 按键**不落盘** | 只收**虚拟键码**，不解析成字符；只在内存里保留「最后一个键 + 计数」，重启即清零 |
| Shift / CapsLock 状态**不参与** | 否则可以还原出你打了什么 |
| 窗口标题**不留历史** | 只保留"当前"，不建时间线 |
| 服务只监听 `127.0.0.1` | 不暴露到局域网 |
| 数据**不出本机** | 不上传、不云同步 |
| **不用低级键鼠 Hook** | 那是杀软的高危行为；轮询 `GetAsyncKeyState` 足够用 |

> 这几条要在代码注释里写清「**故意的，不要优化掉**」——否则半年后你自己（或 AI）会"顺手"把它改成落盘缓存。

- [ ] 你回来，它**知道**你回来了（不是靠你告诉它）
