# 状态面板与游戏化：把「积累」变成看得见的东西

> 阶段 3 解决「它住在哪」，阶段 4 解决「它怎么知道你在」，这一节解决**「你凭什么想打开它」**。
> 没有这一层，前面做的事你都感觉不到——因为它只在你**主动打开**时才存在。

---

## 一、先分清两层，它们出现的时间点必须不同

这是本项目最重要的一条结构判断。用户曾同时提出两个看似矛盾的要求：

> 「要让他在我的电脑使用中**毫无存在感**但又能促使我完成每天在里面的记录，UI 一定要大胆，不要再收敛，最好是**浮夸炫技**」

**答案不是折中，是分层**：

| 层 | 什么时候出现 | 内容 |
|---|---|---|
| **无感层** | 你**没在看**的时候 | 后台感知、自动累积、把记录草稿**提前写好**、静静待着不打扰 |
| **炫技层** | 你**主动打开**的时候 | 面板、动效、日环、雷达图、入场编排——尽情华丽 |

> **两层的实现可以共用数据，但呈现时机必须分开。** 混在一起的结果是：后台一直在动（费电、卡），或者面板打开时平淡无奇（没欲望）。

## 二、面板该有的东西（按价值排序）

### 1. 属性面板（游戏化的壳）
从阶段 2 的 **L3 人设内容包**里的「RPG 角色面板」直接搬过来——**属性不是编的，是从你的人格档案里长出来的**。

```json
{ "persona": { "level": 19, "xp": 2790, "energy": 7 },
  "stats": [ {"k":"行动力","v":85}, {"k":"抗压","v":62}, {"k":"拒绝力","v":25} ] }
```

**关键**：属性要有**低分**。全是 80+ 的面板是假的，没人信；写着「拒绝力 25」的面板才像他自己。

### 2. 可见的积累（把时间变成形状）
| 形式 | 表达什么 | 为什么比数字好 |
|---|---|---|
| **今日之环**（24 段弧） | 今天哪几个小时在、哪几个小时空 | 一眼看完一整天，不需要读数字 |
| **热力图 / 条纹**（最近 14 天） | 最近的连续性 | 断没断一眼可见 |
| **雷达图**（八维蛛网） | 你的属性分布 | 形状比列表好记 |

> **设计原则：把时间变成形状，把抽象变成可比较（和昨天的自己比，不和全世界比）。**

### 3. 每周自省（7 问）
固定时间（例：周日 20:00）弹几个问题，答案**回写到人格档案**（阶段 2 的更新机制）。
问题必须**从你的材料里长出来**，不要套模板——模板问题会得到模板答案。
> 例：「本周有没有『当场答应』后又后悔的事？」这种问题，只有了解你的人问得出来。

### 4. 账本 / 情报 / 生活件（按需）
本项目里有的：副业账本、每天定时抓取的定制情报（RSS + AI 筛选）、上床线倒计时、天气、番茄钟、API 余额。
> **判断该不该做**：它能不能**自动产生**你已经有的数据？能就做；需要你手填的，一律降级（见阶段 4 的"不许打卡"）。

### 5. 数据出口
一定有导出/备份入口。本项目的一句话警示：「数据只在一个 7KB 的 `state.json` 里，**没有任何出口——文件坏了就全没了**」。

## 三、面板的工程要点

| 要点 | 做法 | 为什么 |
|---|---|---|
| **角色代码只有一份** | 面板与壁纸**共用**同一份宠物代码，不要各画一套 | 本项目吃过亏：同一只角色两套实现，最常用的入口功能最弱，改一次要改两遍 |
| **动效要成体系** | 时长令牌（`--dur-1~4`）+ 缓动分工（**入场 `ease-out` / 退场 `ease-in`**）+ 退场与入场对称 | 零散魔法数会让手感不统一；只做入场不做退场，观感是"拖" |
| **过渡挂在状态类上** | 过渡写在 `.off` / `.hide` 这类**隐藏态类**上，不要写在元素本体 | 写在基础规则上 = 元素永远卡在半透明（本项目踩了 **5 次**） |
| **必须有空态** | 后端不可用 → 每个区域**超时判定**（例 6 秒）+ 一句人话 + 重试按钮 | 否则服务一断，界面永远显示"加载中…"，断网即死 |
| **深链** | 支持 `?focus=某个面板`，可从壁纸/通知直接跳进去 | 少一次点击，使用率明显不同 |
| **别加 emoji** | 图标自绘 SVG | 见阶段 3：这是单条性价比最高的"去模板感"手段 |

### 一个反直觉的性能点
**面板的动画开销，可能比 3D 宠物还大。** 本项目的卡顿真凶不是 GPU，而是 **9 处 `backdrop-filter`**——它们的代价与"背后有没有每帧变化的图层"成正比：背后是全屏粒子 canvas 时，等于**每帧做 9 次全屏模糊**。
> **修法**：换成"高不透明度底色 + 更强边框"，观感几乎一致，开销归零。

## 四、产出物与验收

**产出物**：一个能被打开、能一眼看到积累、能在每周问你几个问题的界面。

- [ ] 打开面板，**3 秒内**能看出"今天陪了多久""最近断没断"
- [ ] 属性条里有**真的低分**（不是全 80+ 的假面板）
- [ ] 每周自省的问题**只对你成立**（发给别人会觉得莫名其妙）
- [ ] 答案**真的回写**到了人格档案（去文件里确认，不要信界面）
- [ ] 服务断掉时，界面给出**人话 + 重试**，而不是无限"加载中"
- [ ] 面板与壁纸的**角色行为一致**（同一个角色，不是两个近似品）
- [ ] 动效：有入场**也有退场**，缓动分工正确，`reduced-motion` 下**压到 1ms 而不是删掉**（删掉会让状态机卡住）
- [ ] 有导出/备份入口

## 五、常见失败

| 症状 | 真凶 | 修法 |
|---|---|---|
| 等级涨了但没感觉 | 只有数字没有形状 | 上日环/热力图/雷达图 |
| 打开面板没什么可看 | 数据都在后台，没做可视化 | 补"可见的积累" |
| 面板打开卡一下 | `backdrop-filter` / 大面积 `drop-shadow` / 常驻 `will-change` | 换静态光晕；`will-change` 按需挂 |
| 元素永远半透明 | 过渡写在了基础规则上 | 挪到隐藏态类 |
| 服务一断就白屏 | 没有超时分支 | 每个区域加超时 + 空态 |
| 属性和本人不像 | 属性是编的，不是从人设包来的 | 回阶段 2 取 L3 |
