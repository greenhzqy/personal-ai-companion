# 快速开始：怎么起手，以及四种入口

> 这份文件承接 `SKILL.md` 的「阶段 0」——**起手怎么问、答案怎么判、从哪切入**的完整说明。
> 什么时候读：刚接到一个人、还没决定从哪个阶段开始的时候。

---

## 一、阶段 0 的三问要怎么问

**不要先问技术栈**（用什么语言、什么框架、要不要 GPU）——技术路线由这三问决定，顺序反了会做错东西。

### 问法（照这个来）

| # | 问什么 | 为什么它排在这里 |
|---|---|---|
| 1 | **形态**：「你想让它长什么样、以什么形式陪着你？」 | 决定它**在不在你的视野里** |
| 2 | **屏幕**：「你一天里最常看哪块屏？」 | 决定**优化方向**——最常看的屏值得投入，没人看的屏拉满帧率是纯浪费 |
| 3 | **管什么**：「陪伴 / 推进主线 / 记作息 / 攒钱，你要哪几件？」 | 决定**状态数据长什么样** |

### ★ 第一问的铁律：**不许推荐默认形象**

**先问开放式的**，等他答完，**再**拿举例帮他收敛。顺序反了就是灾难：

```
❌ 错：「你想让它做成桌面壁纸里的角色吗？」   ← 他会顺着答"行"
✅ 对：「你想让它长什么样、以什么形式陪着你？」 ← 先让他自己说
      他答完再问：「比如壁纸里的角色、悬浮球、托盘图标、手机小组件——你偏向哪种？」
```

**为什么这条被单列成铁律**：

1. **形象与人格一样，只能由本人提供**（铁律一）。AI 先抛一个具体形象，等于替他做了决定；
2. **默认值会一路带进阶段 3**：载体选型、渲染方式、护屏策略全都跟着第一问走，**改起来很贵**；
3. **本 skill 的完整实例恰好是壁纸形态**——所以"抄一个壁纸角色"是**最容易发生的偏离**。
   作者本人对这条的原话是：「**形象应该由他们自己设定**，但我踩过的坑应该写出来。」

> 括号里的形态（壁纸角色 / 悬浮球 / 托盘 / 小组件）**是候选举例，不是推荐排序**。
> 写进文件时必须标成"比如"，**不要念成"你要不要壁纸里的角色"**。

### 第三问要附带问「入口」

「管什么」之后补一句：

> 「你是只想让它自己待着，还是还想要一个**工作台**——一个目录，加一套固定说法来指挥它？」

**形态决定它在哪；入口决定你怎么叫它。** 两者独立，都要问（详见第三节）。

## 二、答案怎么落盘

存成 `开工三问.md`，**一句话一答即可**：

```markdown
# 开工三问（YYYY-MM-DD）

形态：壁纸里的角色（他自己说的：想让它住在桌面背景里）
屏幕：工位那台，长期开机，用平板远程（＝同一块屏）
管什么：陪着我 + 推进主线
入口：只要它本身（不要工作台）
```

> **必须落盘，不要只留在对话里。** 验收实测过：不落盘，后面阶段 1/3/4 的**路由依据就丢了**——
> 执行者会凭印象重问一遍，或者按错的假设往前走。

### ★ 落盘时必须带确认标记

```markdown
本人确认：✅ YYYY-MM-DD   ｜   或   ⏳ 待确认
```

**这条是从一次真实事故里来的**：曾经有一条**测试用的假答案**以"已落盘"的姿态，
差一步就变成了后续阶段的依据。**档案模板一直有 `本人确认：` 这一行，阶段 0 的落盘格式却没有。**
现在补上了，两边一致。

**规则**：
- 自签可以，但**必须写日期**；
- 明显是猜的、或他没细看的，写 `⏳ 待确认`，**不要写 ✅**；
- 阶段 2 完成时回头统计一次还有几处 `⏳`，逐条去问。

## 三、四种入口：**形态决定它在哪，入口决定你怎么叫它**

`SKILL.md` 的阶段 0 第一问只覆盖了"形态"。**入口是另一个维度**，同样要问。

| 入口 | 长什么样 | 适合谁 | 代价 |
|---|---|---|---|
| **① 只有它本身** | 桌宠/悬浮球自己待着，你被动接收 | 大多数人；**默认推荐** | 你想让它做件事时，只能对着它说话 |
| **② 工作台目录** | 一个固定目录，里面是**按用途分好的产出物**（职业规划 / 简历 / 情报 / 复盘…） | 已经在用 AI 干活、产出物多的人 | 要维护目录结构，容易散 |
| **③ 固定暗号** | 一套**约定好的说法**，说一句就触发一整套流程 | 长期用、懒得每次解释需求的人 | 暗号要写下来，否则半年后自己都忘了 |
| **④ 都做** | 工作台 + 暗号 + 它本身 | 已经跑通一轮的人 | 协议有两套以上就会乱 |

### ★ 为什么「暗号」值得写成正式的一类

**它是使用者反复迭代出来的协议，比每次临时下指令可靠得多。**
临时指令每次都要重新解释背景；暗号是**压缩过的上下文**。

一个真实的暗号表长什么样（**实录，可照抄结构**）：

| 暗号 | 触发什么 |
|---|---|
| 「加载人格」 | 读人格档案 + 记忆库入口，接上上次的状态 |
| 「今日整理」 | 归档当天进展，同步更新知识库与台账 |
| 「写进第二大脑」 | 把当前结论按笔记规范落库 |
| 「整理大脑」 | 清收件箱、查悬空链接、升格草稿、更新索引 |
| 「更新人格」 | 把新变化写回人格档案并记一行修订日志 |

**暗号的三条设计规则**：

1. **每条暗号对应一整套动作**，不是"打开某个东西"——它省掉的是**解释需求的那几轮**；
2. **暗号表要落在文件里**（`DSH.md` 那种常驻纪律文件），不能只活在聊天记录；
3. **暗号数控制在 5–10 条**。太多了记不住，等于没有。

### ⚠️ 采到暗号就**直接沿用**，不要另起一套

如果使用者已经有一套协议，**照他的来**——
两套协议并存 = 必然混乱（他会不知道该说哪句，你也不知道该听哪套）。

> 这和采集那一节的规矩是同一条：**已有资产的人，先盘清再动手**，不要从零重建。
> 见 `references/1-采集与访谈.md` 的「★ 零、先做资产盘点」。

## 四、按用户类别决定从哪切入

| 他是什么情况 | 从哪开始 | 为什么 |
|---|---|---|
| **只有想法，素材为零** | **阶段 1 采集** | 最花时间也最值钱的一段。跳过它，后面全是编的 |
| **已经有剖析 / 日记 / 简历等材料** | **直接阶段 2** | 不用重做访谈；**但先做资产盘点**（清单勾选），别直接开写 |
| **只想先看个能跑的东西** | **阶段 3 最小可运行版** | 但必须说清代价（见下） |

### ⚠️ 走"先做个 demo"这条路，必须说清放弃了什么

**没有阶段 2，就没有**"只对你成立"的台词与性格，也没有阶段 4 里"它知道你在不在"的判据来源。

所以走这条路时要**同时做三件事**：

1. **明确告诉用户**：这是**一次性 demo**，不是那套系统；
2. **划掉阶段 4 里依赖人格包的验收标准**（例如"它说的话只对你成立"），
   改成"它按状态说了不同的话"——**别把做不到的验收留在清单上装作能过**；
3. 想长期用，**回头补阶段 1、2**，成本比想象中低（骨架已经在跑了，补档案不用改代码）。

## 五、七种常见失败模式（**开工前先给他打预防针**）

| 失败模式 | 症状 | 对策 |
|---|---|---|
| **人格是编的** | 用户看档案说「这不像我」 | 铁律一；**没采集的写「未采集」，绝不代填** |
| **要求打卡** | 两周后没人打开 | 感知层 + 自动累积，不要任何"签到"动作（`references/4-感知与陪伴闭环.md`） |
| **优化了没人看的屏幕** | 耗电发热，体验没变 | 阶段 0 第 2 问问清楚 |
| **它只会弹通知** | 用户把它静音/卸载 | 主动说话必须有**节流与不打扰区间**（人离开就别说话） |
| **数值涨了但没感觉** | 等级涨了，用户无感 | **可见的积累 > 数值**：把时长变成能看的形状（环、轨、热力图） |
| **挂在工位没人知道** | 崩了三天才发现 | 自愈看门狗（`references/5-工程化与护屏.md`） |
| **发布时泄了隐私** | 真名/学校/私人待办进了公开仓库 | **脚本全量扫描**，不靠印象（`references/7-发布与脱敏.md`） |

> **这七条有个共同点**：它们**都不是技术问题**。
> 前两条尤其致命——**做出来的东西"不像他"或者"要他伺候"，那它两周内必死。**
> 所以打预防针的时机是**阶段 0**，不是出事之后。
